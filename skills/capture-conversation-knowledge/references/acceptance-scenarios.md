# Acceptance scenarios

Use these scenarios when changing capture, lifecycle, cursor, or export behavior:

1. Multi-turn co-creation becomes a deduplicated framework, not a chronological transcript or repeated “recorded” notices.
2. A valuable command or product action becomes an operation card with actual effect, verification, risk, and reversibility; read-only inspection is not described as mutation.
3. A disproved hypothesis is revised or superseded so the old claim is no longer an active fact, while a reusable diagnostic correction path may remain.
4. Pause emits no new cards after the persisted boundary; resume returns that boundary; “only new” uses a real cursor.
5. Re-submitting the same host turn is idempotent and does not duplicate turns or cards.
6. An unfamiliar domain still yields useful knowledge without relying on seeded keywords.
7. Export reconstructs a standalone document by dependency, uses the latest supported conclusion, labels material uncertainty, and omits execution noise.
8. A secret-like value is redacted from stored/sent learning material and never appears in logs or fixtures.
9. Without a state store or UI, the Skill states the limitation and still produces a useful visible export without claiming persistence.
